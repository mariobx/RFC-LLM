The Cryptographic Protocol Shapes Analyzer (CPSA) attempts
to enumerate all essentially different executions possible for a
cryptographic protocol. We call them the shapes of the protocol.
Naturally occurring protocols have only finitely many, indeed very
few shapes. Authentication and secrecy properties are easy to
determine from them, as are attacks and anomalies.

This presentation gives a very brief tour of the tool and how it
is used in practice.


                                                               2-1
Anatomy of a CPSA Installation

    • Programs
      – cpsa4: main analysis tool
      – cpsa4shapes: extracts shapes from cpsa output
      – cpsa4graph: visualize output using XHTML and SVG
      – cpsa4diff: compare two cpsa output files
      – cpsa4sas: produce shape analysis sentences
      – cpsa4pp: pretty print input and output
      – Build tools: GNU makefile template and a Haskell script
    • Documentation
      – User documentation: user guide, primer, and goal descrip-
        tion
      – Sample input: Needham-Schroeder, Blanchet, Woo-Lam,
        Otway-Rees, Yahalom, ffgg, goals, rules

                                                          3-1
Using CPSA

    • With a text editor, user enters a description of a

      – protocol as a set of roles
      – problem point-of-view
        (what is assumed to have happened)


    • User runs the tool ($ echo build | ghci Make4.hs
      or on Windows, click on Make4.hs and type build)


    • In a web browser, user views the output that shows

      – what else CPSA inferred must have happened, or
      – all CPSA steps used to produce the answers

                                                            5-1
Blanchet Protocol in CPSA

    (defprotocol blanchet basic
      (defrole init
        (vars (a b name) (s skey) (d data))
        (trace
         (send (enc (enc s (privk a)) (pubk b)))
         (recv (enc d s))))
      (defrole resp
        (vars (a b name) (s skey) (d data))
        (trace
         (recv (enc (enc s (privk a)) (pubk b)))
         (send (enc d s)))))

13
The corrected protocol ensures the critical message refers to b.
As a result, CPSA infers the desired agreement.




                                                            13-1
Corrected Blanchet Shape

     (defskeleton blanchet-fixed
       (vars (d data) (a b name) (s skey))
       (defstrand resp 2 (d d) (a a) (b b) (s s))
       (defstrand init 1 (a a) (b b) (s s))
       (precedes ((1 0) (0 0)))
       (non-orig (privk a) (privk b))
       (uniq-orig s)
       (operation encryption-test
         (added-strand init 1)
         (enc s b (privk a))   ; Critical message
         (0 0))
       ...)
